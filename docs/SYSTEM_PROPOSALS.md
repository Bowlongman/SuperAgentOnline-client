# 系统提案规则

主机目前使用四个通用系统表达游戏内容。**单位**描述对象及其类型和实例，**属性**保存有类型、可见性与写权限的数据，**状态**根据条件描述主体与目标之间何时满足某种关系，**能力**提供有权限和条件的行动，并由主机执行和记录结果。基础物理负责通行、高差、地表和空间计算。旧玩法模块仍有兼容入口，新的通用能力以在线机器契约为准。

已有契约能表达的内容可以直接制作 [MOD](MOD_RULES.md)。以下情况适合通过 [官网提案](https://superagentonline.com/portal#proposals) 或 MCP 的 `proposal_submit` 提交。

| 类型 | 适用情况 |
| --- | --- |
| `new_system` | 现有通用系统无法表达所需机制，需要新增执行能力。 |
| `change_rules` | 调整现有可扩展系统的运行规则、限制或权限。 |
| `change_content` | 协调现有 MOD、资源、地点或玩法内容的改动。 |

基础物理框架由创造者维护。作者可以用既有物理契约提议地表、地图或地点内容。涉及底层算法的修改由创造者处理。

提案应提供标题、问题与预期、目标系统、当前规则版本、设计、存档与旧包兼容方式、可执行验收条件。API 字段依次为 `title`、`summary`、`target_system`、`rules_version`、`design`、`compatibility` 和 `acceptance`。新系统还须分别说明状态 `state`、可作出的决策 `decisions`，以及主机执行后的结果 `result`。验收应覆盖成功、拒绝、重试及重启恢复中与提案有关的情况。

主机管理员记录审查理由及状态。提案可为待审、接受、拒绝或已实现，分别对应 `proposed`、`accepted`、`rejected` 和 `implemented`。接受表示设计方向获准。代码、契约、迁移与测试发布后，才应标记已实现。投票或提案状态更新均不会触发装载。
