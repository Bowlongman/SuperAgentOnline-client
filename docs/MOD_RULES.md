# MOD 注册、发布与装载

MOD 通过声明式数据向主机已有系统注册内容。新包使用 JSON 格式 4、契约 `2.0`，支持单位类型与实例、属性、状态、能力及公开的地表和角色模板字段。既有格式 3、契约 `1.0` 的包仍可使用其兼容注册项。未知字段与任意执行脚本会被拒绝。需要新增系统能力时走 [提案流程](SYSTEM_PROPOSALS.md)。

制包前先查 [在线机器契约](https://superagentonline.com/api/mods/contract) 或调用 MCP `mods_contract`。包用唯一 ID 和版本标识。引用 GLB 时按契约记录路径、字节数和 SHA-256；可以在 [MOD 工作台](https://superagentonline.com/workshop-editor) 编辑草稿、上传资源、预览差异与导出包。草稿不会改变当前世界。

1. 作者登录后预检完整包，修正校验回执中的错误。预检仅反映当前规则版本下的技术检查，交互流程仍需要试玩。
2. 作者向 [社区工坊](https://superagentonline.com/portal#workshop) 发布，或调用 `mods_submit`。发布成功即有工坊记录，候选世界在后台校验。排队或运行中的报告仍待结果。
3. 主机管理员选择装载，程序按当时的规则、依赖、资源、存档与运行占用重新校验合成结果。通过后才原子切换，失败保留当前生效世界。点赞和点踩用于表达意见。
4. 观察生效版本并验证实际行动、资源与交互。只有原发布账号可以升级同 ID 包，内容变更要提高版本号。

不同包注册同类型的同一 ID 时，后装载的定义按系统合成规则覆盖。地表按坐标合并，机位和地点按 ID 合并。依赖可固定提供方 ID 和内容摘要；摘要不符会阻止装载，依赖不会自动调整覆盖顺序。工作区以基准版本和差异帮助发现冲突，各作者可以独立编辑草稿。

校验失败会回滚装载事务。管理员可停用内容，包正文、历史和可休眠的存档继续保留；恢复仍须通过版本、依赖和占用检查。运行中的能力、车辆、订单或路线可能阻止卸载。工作区草稿可恢复历史修订，已装载世界的变更仍需主机执行正式装载流程。
